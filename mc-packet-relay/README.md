# Minecraft Packet Relay

自作Minecraftサーバーとの通信テスト用の、**単体で動く中継(プロキシ)ツール**です。
外部ライブラリ不要・Minecraft本体やバージョンにも依存しないため、ダウンロードしたjarを
そのまま実行するだけで使えます（ビルド不要）。

## なぜMOD(mods フォルダに入れる形式)ではないのか

同じフォルダにある `../packet-toggle-mod/` は本来のFabric MOD（mods フォルダにポン入れする形式）
として実装していますが、ビルドには Fabric 独自の依存関係（Yarn mappings・Fabric API・Fabric Loader）
が必要で、これらは `maven.fabricmc.net` からしか取得できません。今回の作業環境ではこのホストへの
アクセスがネットワークポリシーでブロックされており、jarを生成できませんでした。

このツールはその代替として、**Minecraftのマルチプレイ「サーバーアドレス」を向け先として設定するだけ**
で同じ目的（自作サーバーとの通信を意図的に止める/遅らせる）を果たせるようにしたものです。
JDK標準機能だけで書かれているため、この場でビルド・実機テストまで完了させています。

## 使い方

1. `mc-packet-relay.jar` をダウンロードする
2. 自作サーバーへ直接ではなく、このツール経由で接続するように起動する

   ```bash
   java -jar mc-packet-relay.jar [待受ポート] [本来のサーバーホスト] [本来のサーバーポート]
   # 例: 自作サーバーが localhost:25565 で動いている場合
   java -jar mc-packet-relay.jar 25566 localhost 25565
   ```

   引数を省略した場合のデフォルトは `25566 localhost 25565` です。

3. Minecraft側のマルチプレイ「サーバーを追加」で、サーバーアドレスを

   ```
   localhost:25566
   ```

   （上記コマンドで指定した「待受ポート」）に設定して接続する

4. ツールを起動したターミナルにコマンドを打つと、クライアント→サーバー方向の送信を切り替えられる

   | コマンド | 内容 |
   |---|---|
   | `stop` | 送信停止トグル。ONにすると以後の送信データを完全に破棄する。もう一度打つとOFF。 |
   | `delay <ms>` | 送信遅延トグル。ONにすると以後の送信データを指定ミリ秒だけ遅らせて転送する。もう一度 `delay` （引数なしでも可）と打つとOFF。 |
   | `normal` | 停止・遅延を解除して通常状態に戻す |
   | `status` | 現在の状態を表示 |
   | `help` | コマンド一覧を表示 |
   | `quit` | ツールを終了 |

サーバー→クライアント方向（受信）は常にそのまま中継されます（操作対象はクライアント→サーバー送信のみ）。

## 動作確認について

このテキストの作成過程で、ダミーのTCPサーバー・クライアントを使い実際にJVM上で動作検証を行い、
以下を確認しています。

- 通常モード: 送信後 数十ms 以内に相手へ届く
- `stop` ON: 送信したデータが相手に一切届かない（トグルOFFにしても、既に破棄したデータは復活しない）
- `delay 1000` ON: 送信データが約1000ms遅れて相手に届く

## ソースからビルドする場合

```bash
javac -encoding UTF-8 PacketRelay.java
jar --create --file mc-packet-relay.jar --main-class PacketRelay PacketRelay*.class
```

## 注意

- あくまで自分が管理するサーバーとの通信テストを目的としたツールです。他人が運営するサーバーや、
  対戦相手に対して不正な優位性を得る目的での利用は想定していません。
- 長時間 `stop` のままにすると、サーバー側のタイムアウト処理により切断されるのは想定内の挙動です。
