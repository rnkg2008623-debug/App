# Packet Toggle Mod

自作Minecraftサーバーとの通信テストを目的とした、**Fabric向けクライアントMOD**です。
クライアント→サーバーへ送るパケット送信を、キー操作で

- **STOP**: 完全に送信を止める（そのパケットは破棄される）
- **DELAY**: 指定した時間だけ送信を遅らせる（キューにため、時間が来たら送る）

のどちらかにトグルできます。自作サーバー側のタイムアウト処理・再接続処理・ラグ耐性などを
手元で検証するためのツールです。**他人が運営するサーバーでの利用や、対戦相手に対する
不正な優位性の取得を目的とした利用は想定していません。**

## 前提

- Minecraft: 1.21.x系（`gradle.properties` は 1.21.1 を仮の基準値にしています）
- Modローダー: Fabric
- Java 21以上
- ビルドにはインターネット接続（Fabricのメイヴンリポジトリ・Minecraft本体のダウンロード）が必要です

> **重要な注意（バージョン文字列について）**
> この環境ではネットワーク制限のため `https://fabricmc.net/develop/` や
> Fabricの公式Mavenリポジトリに接続してバージョンを確認できませんでした。
> `gradle.properties` の `yarn_mappings` / `loader_version` / `fabric_version` は
> 執筆時点の知識に基づく暫定値です。**ビルド前に必ず https://fabricmc.net/develop/ で
> 対象Minecraftバージョンの最新値を確認し、必要なら書き換えてください。**
> 値が古い場合はGradle依存解決の段階で明確なエラーになるので、そのバージョン文字列を
> 現在の値に更新すれば解決します。

## ビルド方法

```bash
cd packet-toggle-mod
# Gradle Wrapperを同梱していないため、ローカルのGradle（8.8以降推奨）で生成するか、
# IntelliJ IDEAでこのフォルダを開いてGradleプロジェクトとして読み込んでください。
gradle wrapper --gradle-version 8.10
./gradlew build
```

ビルドが成功すると `build/libs/packettoggle-1.0.0.jar` が生成されます。
このjarをMinecraft本体+Fabric Loaderのmodsフォルダに入れて起動してください
（サーバーではなくクライアント側です。`fabric.mod.json` で `"environment": "client"` に
しているため、サーバーにこのMODを入れても何も起きません）。

## 使い方

初回起動時はどのキーにも割り当てられていません。ゲーム内の
**設定 → コントロール → キー割り当て** を開き、「パケットトグルMOD」カテゴリで
好きなキーを割り当ててください。

| 操作 | 内容 |
|---|---|
| パケット送信 停止トグル | ONにすると、以後のクライアント→サーバー送信パケットを全て破棄する。もう一度押すとOFF（通常送信に復帰）。 |
| パケット送信 遅延トグル | ONにすると、以後の送信パケットを現在の遅延時間だけ経過してから送信する（キューイング）。もう一度押すとOFF。OFFにしても、既にキューにあるパケットは順次送信される。 |
| 遅延時間を増やす / 減らす | 遅延時間を100ms単位で調整（0〜60,000msの範囲）。 |
| キュー内のパケットを即時送信 | 遅延キューに溜まっているパケットを全て今すぐ送信する。 |

現在の状態は画面左上に小さくHUD表示されます（STOP中・DELAY中・キュー件数がある場合のみ表示）。
チャットにも切り替え時にメッセージが出ます。

## 仕組み（実装メモ）

`net.minecraft.client.network.ClientCommonNetworkHandler#sendPacket` にMixinで割り込み、
プレイ中（`ClientPlayNetworkHandler`）のパケット送信のみを対象にトグル状態を反映しています。
- STOP時: `CallbackInfo#cancel()` でそのまま送信をキャンセル（破棄）
- DELAY時: 送信をキャンセルし、パケットを内部キューに保持。クライアントTickごとに
  遅延時間を過ぎたものだけ、割り込みを回避するフラグを立てて再送する

ログイン・構成フェーズのパケット（サーバー接続確立まで）は対象外にしているため、
このMOD自体でサーバーに繋げなくなることはありません（プレイ開始後に操作してください）。

## 既知の制約

- 対象はプレイ中の送信パケット全般（移動・チャット・インベントリ操作・キープアライブ応答など）です。
  意図的に「サーバーとの通信を止める/遅くする」ことが目的なので、キープアライブ応答も
  対象になります。長時間STOPのままにすると、サーバー側のタイムアウトで切断されるのは想定内の挙動です。
- DELAYモード中に遅延時間を変更すると、キュー内のパケットは基本FIFOで処理されるため、
  厳密には新しい遅延値がすぐ全パケットに反映されるわけではありません（テストツールとしては
  十分な精度として簡略化しています）。
- Yarnマッピングのメソッド名・シグネチャはMinecraftバージョンによって変わることがあります。
  別バージョンに対応させる場合は、開発環境で `ClientCommonNetworkHandler` の実際の
  `sendPacket` シグネチャを確認し、`ClientCommonNetworkHandlerMixin` の `method` 属性を
  必要に応じて調整してください。
